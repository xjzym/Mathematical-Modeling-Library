# 【模型 01 · LSTM】AI 协作提示词模板

> 用途：在**不同背景、不同数据集**下复用本模型时，直接把对应模板交给 AI 助手。
> 配套文件：`代码/lstm_template.py`、`代码/config_mcm2025C.json`、`01_LSTM_模型清单.md`

---

## 模板 1 ｜迁移到新数据集（最常用）

```
【任务】把已复现的 LSTM 时序趋势模型（见附件 01_LSTM_模型清单.md）迁移到新数据集，产出可交付的趋势特征。

【已有资产】
- 通用模板：代码/lstm_template.py（配置驱动，已验证与专用实现逐位一致）
- 配置样例：代码/config_mcm2025C.json
- 模型卡：01_LSTM_模型清单.md（含公式、口径、坑清单）

【新数据集】
- 文件路径：<填>                       # 长表 CSV
- 实体列：<填>   期次列：<填>   目标列：<填>
- 事件/主办表（可选）：<填>            # 没有就写“无”，模型会自动降级为单通道
- 需要外推的期次：<填>                  # 例如 2030
- 验证期次：<填>                        # 例如最后两期，按时间留出

【必须遵守】
1. 输出必须与输入同尺度（反标准化），并附多种子（≥5）的标准差；
2. 标准化统计量只能用训练样本；禁止窗口包含目标期（t→t+1）；
3. 先交付 dry-run 自检（面板规模、样本数、正样本比例），确认后才训练；
4. 报告指标只用 MAE / WMAE / RMSE（若目标含大量 0，禁用 MAPE）；
5. 任何结论都要说明“是否有多种子与配对检验支撑”。

【交付物】
1. 可运行代码（配置驱动）+ 配置文件；
2. trend_history.csv / trend_future.csv（键 = 实体 + 期次，含 std）；
3. 指标表 + 训练曲线图；
4. 一页说明：数据口径、坑、限制、与上一个数据集的差异。

【先回答我】在动手前，列出你对这份新数据集**尚不确定的 3 件事**（口径/缺失/异常），我会逐条确认。
```

## 模板 3 ｜调参与实验（防止把噪声当结论）

```
【任务】对模型 01 的下列超参数做实验，并给出**有统计支撑**的结论。
参数：<例如 hidden_size ∈ {32,64,128} × patience ∈ {6..10}>
数据/口径：严格沿用已交付配置（见 01_LSTM_模型清单.md 第 6.2 节）

【硬性要求】
1. 每个配置至少 5 个随机种子，报告 mean ± std，并保留每次运行的原始记录；
2. 报告“单次运行的取值范围”，用于判断差异是否只是种子噪声；
3. 做**配对检验**（同种子相减，n=5，t 临界值 2.776），明确写出哪些差异显著；
4. 若差异不显著，必须直接说“该超参数在本数据上不可辨识”，不要包装成“更优”；
5. 可利用“一次长训练派生整条 patience 扫描”的省算力性质（见模型卡 3.4），但必须先用 --dry-run 或单配置验证一致性（最大差 < 1e-4）。

【交付】
- results.csv（逐次运行）、summary.csv（mean/std）、配对检验表；
- 一张对照图（含误差棒）；
- 结论段落：能用 / 不能用这个超参数解释什么。
```

## 模板 5 ｜设计三类规范（输入向量 / 损失函数 / WMAE）

```
【任务】为新数据集设计 LSTM（模型 01）的三项核心规范：① 每个时间步的输入向量 ② 损失函数 ③ WMAE 指标。
参考：01_LSTM_模型清单.md 第七节（方法论 + 检查表）、代码/metrics_utils.py（可调用工具）。

【数据情况】<填：实体/期次/目标列/样本量/是否能拿到事件表/目标是否有 0 值或重尾>

【要求按这个顺序回答】
1. 输入向量：
   a) 列出候选特征并分类（自回归项 / 实体固有属性 / 阶段状态项）；
   b) 对每个特征标注：时间语义、在预测时刻是否可得、量纲、是否需要标准化、进入哪个通道；
   c) 给出“公布时间”表，明确指出**哪些特征必须剔除**（防泄漏与未来不可知）；
   d) 用 metrics_utils.audit_features() 的输出格式给出审计结论。
2. 损失函数：
   a) 主任务形式（MSE / Huber / 分位数）及理由，说明目标是否重尾；
   b) 是否加辅助任务，若加，给出标签来源、正类比例与 bias 先验；
   c) 尺度策略（在哪个尺度算损失、在哪报指标）；
   d) λ 的取值方法（优先“量级对齐”，给出 recommend_lambdas 的结果）；
   e) 死项与量级失衡的自检方式。
3. WMAE：
   a) 说明“错谁更疼”，据此选权重来源；
   b) 给出 w 的具体公式与 w=0 的处理方案；
   c) 计算 N_eff 与零权样本占比；
   d) 给出同时汇报的对照指标（无权 MAE / RMSE）；
   e) 列出该指标**不能**用于什么（如含 0 目标时禁用 MAPE）。
4. 一致性：给出“口径 → 尺度 → 权重 → 显著性”四步自检的结论。

【硬性要求】
- 每个设计选择都必须写“为什么”，并指出**若选错的后果**；
- 凡涉及“A 比 B 好”，必须说明是否需要多种子 + 配对检验；
- 输出一份可直接粘贴进模型卡的 Markdown 小节。
```
