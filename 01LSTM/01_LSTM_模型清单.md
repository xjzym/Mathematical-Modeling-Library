## 一、【模型解决的问题】

### 1.1 直接解决的问题

把**离散、不等间隔、长短不一、含噪声的实体时间序列**，压缩成可用于下游预测模型的**趋势特征**，并同时识别“外生事件”（如主场、政策、赛事改制）的影响。

在本项目中的具体形态：

| 问题 | 说明 |
|---|---|
| 输入 | 82 个国家 × 19 届奥运会（1952–2024）的金牌数、奖牌总数序列；主办国信息 |
| 输出 | ① 每个 (国家, 目标届) 的**一步预测趋势值**（Gold/Total）；② 2028 年外推趋势值；③ 主场识别概率（辅助任务） |
| 下游 | 交给 XGBoost-Bootstrap，与 PCA 主成分、主场效应一起做最终奖牌预测与区间估计 |

### 1.2 通用化后能解决的问题类型

| 场景 | 映射方式 |
|---|---|
| 世界杯/联赛球队战绩趋势 | 实体=球队，期次=赛季，目标=积分/进球 |
| 公司营收与政策效应 | 实体=公司，期次=年份，事件=补贴/上市 |
| 城市人口、能源消耗 | 实体=城市，期次=年份，事件=新区设立 |
| 赛事改制/规则变更的影响 | 事件列 + Prep 窗口自动刻画“事件前若干期的预热效应” |
| 稀疏小样本实体的外推 | 目标补 0 + 事件通道 + 多任务正则，天然抗稀疏 |

### 1.3 与相邻模型的边界（**不要越界使用**）

- ❌ 它**不做区间估计**（Bootstrap/分位数回归是 02 号候选模型的职责）；
- ❌ 它**不做因果推断**（DID 是后续模型的职责）；
- ❌ 它的输出**不是最终预测**，只是“长期水平 + 趋势”的正则化估计（实例：英国 2028 趋势 28.3，而 2024 实际仅 14）；
- ✅ 它**最擅长**：把历史序列变成“低维、平滑、可解释、可外推”的特征。

## 二、【模型的优缺点】

### 2.1 优点

| # | 优点 | 证据 / 说明 |
|---|---|---|
| 1 | **能捕捉长程依赖** | 门控单元状态提供了近乎无衰减的记忆通道，跨 4 年一届的稀疏采样仍能保留“连续三届增长”这类信息 |
| 2 | **抗噪、抗稀疏** | 多任务损失（回归 + 事件识别）起到正则化作用；对只有 5–10 期记录的小实体也能给出稳定趋势 |
| 3 | **双通道解耦异质变量** | 成绩序列与事件特征量纲、语义不同，分通道避免互相干扰；消融显示事件通道让验证 WMAE 降低 |
| 4 | **输出可直接下游复用** | 趋势值是连续标量，天然可作为树模型/线性模型的特征，且与原始量纲一致（已反标准化） |
| 5 | **不确定性可量化** | 多种子训练给出 `*_std`，直接反映模型的稳定性，供下游做稳健性分析 |
| 6 | **完全可复现** | 固定三处随机种子（random/numpy/torch）+ CPU 训练 4–5 秒/次 |
| 7 | **配置驱动、可跨数据集复用** | 本清单的 `lstm_template.py` 通过一份 JSON 配置即可换数据（已在本项目逐位验证） |
| 8 | **省算力技巧** | 一次 `patience=max` 的长训练可派生整条 patience 扫描（已实证，最大差 2.4e-7） |

### 2.2 缺点与规避

| # | 缺点 | 后果 | 规避手段 |
|---|---|---|---|
| 1 | **单次运行噪声大** | 同一配置换种子，验证 WMAE 可差 2–7 枚奖牌 | 必须多种子平均（≥5）+ 报告 std；配置间比较必须做配对检验 |
| 2 | **趋势值 ≠ 预测值** | 直接当预测用会严重偏离（英国 28 vs 14） | 明确定位为“特征”，最终预测交下游模型 |
| 3 | **对突发事件无能为力** | 禁赛、疫情、战争等结构性断点在序列中表现为“真值 0”，模型仍按趋势外推（俄罗斯 2024 → 预测 26.7 金，误差 73 牌） | 加入事件哑变量；或对异常年份做掩码/加权 |
| 4 | **超参数几乎不可辨识** | hidden_size/patience 的配置间差异（0.87/1.89）小于种子噪声（可达 2.81/6.97），配对 t 检验全部不显著 | 不要花时间调 hidden_size；把精力放在特征口径与数据质量上 |
| 5 | **外生事件分类任务易塌缩** | 事件正样本仅 1.2%（14/1148），概率绝对水平不可信（三变体 0.05–0.19） | 用 bias 初始化先验（log(0.1/0.9)）；**不要把概率当特征** |
| 6 | **存在信息泄漏风险** | 若沿用原文“同届对齐”，输入会含目标届真值，指标虚高（实测 WMAE 掉到 0.4–2.7） | 强制 `t → t+1` 对齐；任何统计量只用训练集 |
| 7 | **MAPE 等相对误差指标失效** | 大量实体目标为 0，MAPE 被截断分母放大到 100%+ | 只用 MAE / WMAE / RMSE，或仅对“目标 ≥ 阈值”的子集算 MAPE |
| 8 | **计算成本随 hidden 增大线性上升** | 128 隐层比 32 慢约 2–3 倍 | 小样本场景直接用 32；调参收益本就很小 |
| 9 | **对实体口径极其敏感** | 历史政治实体不合并会把序列切断（如德国=东德+西德），趋势失真 | 显式维护 `entity_merge_map` 并把“同届多实体求和”写进流程 |

## 三、【代码实现提示】

> 完整可用实现：`代码/lstm_template.py`（通用模板）+ `代码/lstm_312.py`（本项目专用，含调参网格/消融/派生验证）。

### 3.1 实现顺序（照此推进，每步可单独验证）

```
① 数据清洗与面板构造  → ② 事件特征（IsHost/Prep/alpha） → ③ 滑窗样本（t→t+1）
→ ④ 标准化（只用训练集） → ⑤ 双通道 LSTM → ⑥ 分层损失与早停 → ⑦ 多种子聚合 → ⑧ 交付表与图
```

**每一步都要能单独跑**：用 `--dry-run` 只做 ①–③ 并打印面板/样本规模（本项目输出：82 实体 × 19 期，1394 样本 = 1312 有标签 + 82 外推）。

### 3.2 形状与类型规范（踩过的坑都在这）

| 对象 | 形状 | 说明 |
|---|---|---|
| `x_main` | `(N, n_steps, n_targets)` | 目标通道；`n_targets=2`（Gold/Total） |
| `x_event` | `(N, n_steps, n_event_feats)` | 事件通道；`[IsHost, Prep, alpha]` 三维 |
| `y` | `(N, n_targets)` | **原始尺度**，只用于算指标 |
| `Y` | `(N, n_targets)` | **标准化尺度**，只用于 loss（⚠️ 传错会导致结果放大约 10 倍） |
| `event_y` | `(N,)` | 目标期次的事件标签（0/1），用于 BCE |
| 窗口 | `[j-n_steps+1, j]` → 目标 `j+1` | 绝不允许窗口包含目标期 |

### 3.3 数值稳定与红线

1. **标准化统计量只能用训练样本**（`mean/std` 从训练窗口算，再作用到全体）；
2. **事件通道只标准化量纲大的列**（alpha），0/1 标志位保持原样——否则结果与预期口径不一致；
3. `float(loss.detach())` 再累加，避免 autograd 警告；
4. BCE 前 `p.clamp(1e-6, 1-1e-6)`；事件正类极稀有 → 分类头 `bias` 初始化为 `log(p/(1-p))`，`p` 取事件基率量级（本项目 0.1）；
5. 早停判据若因权重全 0 变成 NaN，**回退到 MSE**，不要让它静默失效；
6. 权重选择协议必须显式：`select=best`（恢复验证最优权重，推荐交付）或 `select=last`（保留早停时刻权重，用于复现论文式锯齿曲线）。

### 3.4 省算力与调参经验（本项目实证）

- **patience 轴可以“免费”派生**：同一随机种子下，`patience=k` 的结果 = 第（最后一次改进轮次 + k）轮的权重。一次 `patience=10` 的训练可读出 k=6…10 全部结果（实测最大差 2.4e-7）。→ 15 个配置的网格只需 3 次训练（每个 hidden 一次）。
- **配置差异不显著**：配对 t 检验（同种子相减，n=5，临界 2.776）所有两两比较 |t| < 2.5 → **不要用超参数选择来解释性能差异**。
- **要看真实差异**：报告“多种子均值 ± std”，并附“单次运行的取值范围”；论文式的单次运行锯齿（极差 Gold 3.22 / Total 5.28）与我们的单次运行噪声分布（中位数 1.60 / 4.06，95% 上限 2.86 / 7.35）同量级。
- **优先投入顺序**：数据口径 > 特征构造 > 权重选择协议 > 超参数。

### 3.5 迁移到新数据集：4 步

```powershell
# 1) 复制配置模板，只改 data 段
copy config_mcm2025C.json my_dataset.json
# 2) 数据自检（不训练，秒级）
python lstm_template.py --config my_dataset.json --dry-run
# 3) 小样本过拟合测试（验证代码无误：应能拟合到接近 0 误差）
python lstm_template.py --config my_dataset.json --override train.epochs=300 train.patience=50 model.hidden_size=64
# 4) 正式训练 + 交付
python lstm_template.py --config my_dataset.json
```

`data` 段最少只需 4 个字段：`panel_csv`、`entity_col`、`year_col`、`target_cols`；没有事件表时删掉 `host_csv`，模型自动降级为**单通道**（只学趋势，无 BCE 辅助任务）。

## 四、【已经犯的错误和解决办法】

> 下表全部是**本项目真实发生**的错误（含报错信息与修复方式），可直接作为排查手册。

### 4.1 建模与代码类

| # | 错误现象 | 根本原因 | 解决办法 |
|---|---|---|---|
| 1 | 训练能跑，但**没有 2028 预测样本**（预测集为 0 行） | 样本构造只生成“有标签目标”，最后的目标届是 2024，2028 数据不存在 | 单独构造“外推样本”：窗口 = 最后 `n_steps` 期，标签置 NaN，并用 `is_future` 掩码隔离 |
| 2 | `IndexError: list index out of range` | `target_edition` 里既存过下标又存过年份，二次索引越界 | 统一约定：**样本表里只存年份**；转换只做一次 |
| 3 | 预测值放大约 10 倍（美国 351 金） | 训练时把**原始尺度 y** 喂给 loss，预测时又反标准化一次 | loss 必须用标准化后的 `Y`；在 loader 里显式注释该坑 |
| 4 | 通用模板与专用实现结果不一致（WMAE 7.29 vs 8.58） | 模板把事件通道的 0/1 标志位也做了标准化 | 只标准化 `max-min > 1.5` 的列（即 alpha），标志位原样 |
| 5 | BCE 项**梯度恒为 0**，辅助任务无效 | 原文把 $\hat p_i$ 写成常数 0.1，代入后损失与参数无关（$2.197\cdot H/N-\log 0.9$） | 实现为 sigmoid 输出；把 0.1 用作**分类头 bias 先验**（实测该变体最优：WMAE 3.396、AUC 0.957） |
| 6 | 指标异常好（WMAE 0.4–2.7） | 沿用原文“同届对齐”，输入窗口含目标届 Gold → 信息泄漏 | 强制 `t → t+1` 错位对齐 |
| 7 | 验证指标虚高、线下崩 | 标准化统计量用了全量数据 | 统计量只用训练样本 |
| 8 | 早停静默失效 | 早停判据（WMAE）因权重全 0 变 NaN | 判据为 NaN 时回退 MSE |
| 9 | `patience` 改了但结果一模一样 | 采用“恢复验证最优权重”协议时，patience 只影响何时停，不影响选出哪个权重 | 明确两种协议；复现论文锯齿图时用 `select=last` |
| 10 | 把单次运行差异当成“超参数效应” | 未做多种子与显著性检验 | 5 种子平均 + 蒙特卡洛 + 配对 t 检验 |
| 11 | MAPE 高达 85%–125%，无法解读 | 大量实体目标为 0，分母被 `max(|y|,1)` 截断放大 | 弃用 MAPE，改 MAE/WMAE；或只在目标 ≥ 阈值子集上算 |
| 12 | `KeyError: "Column(s) ['Gold_trend_std'] do not exist"` | 分组聚合时引用了尚未生成的 std 列 | 用 `pd.NamedAgg`：`agg(Gold_trend_std=("Gold_trend","std"))` |
| 13 | `UserWarning: Converting a tensor with requires_grad=True to a scalar` | 直接 `float(loss)` 累加 | 改 `float(loss.detach())` |
| 14 | `ValueError: could not broadcast ... (1148,3) into (1394,3)` | 标准化时把“训练子集统计量”赋值回**全体**切片 | 先算 `col[tr]` 的统计量，再对全列做变换 |
| 15 | alpha 特征过大（最大 7.34）导致训练不稳 | 主场增益系数是比值型、重尾 | 训练前对该列做 z-score 标准化；交付表保留原值并提示下游 |

### 6.1 数学原理与公式（速查）

| 公式 | 表达式 | 作用 |
|---|---|---|
| (1) 事件增益系数 | $\alpha_c=\dfrac{\mathrm{Gold}^{host}_c-\mathrm{Gold}^{avg}_c}{\mathrm{Gold}^{avg}_c}$ | 把“该实体发生事件时的表现增益”编码成一维特征（**因果版**：只用目标期之前的历史） |
| (2) 备战窗口 | $\mathrm{Prep}_t=1\ \text{if}\ t\in[t_{host}-W,\ t_{host}]$ | 刻画事件前的“投入/预热”效应（本项目 $W=8$ 年 = 两个奥运周期） |
| (3) 输入向量 | $\mathbf{x}_t=[y^{(1)}_t,\dots,y^{(m)}_t,\ \mathrm{IsEvent}_t,\ \mathrm{Prep}_t,\ \alpha_c]$ | 目标通道 + 事件通道 |
| (4) 双通道 | $\mathbf{h}^{\text{main}}_t=\mathrm{LSTM}_{\text{main}}(\mathbf{y}_{t-k}),\ \mathbf{h}^{\text{evt}}_t=\mathrm{LSTM}_{\text{evt}}(\mathbf{e}_{t-k}),\ \hat y_t=\mathrm{FC}(\mathbf{h}^{\text{main}}_t\oplus\mathbf{h}^{\text{evt}}_t)$ | 异质变量解耦后再融合 |
| (5) 分层损失 | $\mathcal L=\lambda_1\mathcal L_{\text{main}}+\lambda_2\mathcal L_{\text{evt}}$，$\mathcal L_{\text{main}}=\mathrm{MSE}$，$\mathcal L_{\text{evt}}=\mathrm{BCE}$ | 主任务 + 事件识别辅助任务（小样本正则化） |
| (6) 加权误差 | $\mathrm{WMAE}=\sum_c w_c|y_c-\hat y_c|/\sum_c w_c$ | 让“大实体预测错”付出更大代价（本项目 $w_c$ = 真实当届金牌数） |
| LSTM 单元 | $\mathbf f_t=\sigma(W_f[\mathbf h_{t-1};\mathbf x_t]+b_f)$，$\mathbf c_t=\mathbf f_t\odot\mathbf c_{t-1}+\mathbf i_t\odot\tilde{\mathbf c}_t$，$\mathbf h_t=\mathbf o_t\odot\tanh(\mathbf c_t)$ | 门控记忆（论文未列出，实现必须补） |
| 早停 | 验证判据连续 `patience` 轮不改善即停，恢复最优权重 | 小样本防过拟合 |

## 七、【设计方法论】如何设计「输入向量 / 损失函数 / WMAE」

> 这三件事决定模型的天花板：**输入向量决定“能学到什么”，损失函数决定“模型偏向什么”，WMAE 决定“你会挑中哪个模型”**。
> 本节是**可迁移到任何数据集**的设计流程，不是本项目的一次性写法。配套工具：`代码/metrics_utils.py`（`python metrics_utils.py --demo` 一键跑出全部检查结果）。

### 7.1 每个时间步的输入向量 $\mathbf{x}_t$

#### 7.1.1 先分三类构件，再拼装

| 构件 | 定义 | 本项目实例 | 换数据集时对应什么 |
|---|---|---|---|
| **自回归项** | 目标自身的历史值 | $\mathrm{Gold}_{t-k},\ \mathrm{Total}_{t-k}$ | 销量、GDP、积分、客流量 |
| **实体固有属性** | 不随期次变化（或缓变）的实体画像 | $\alpha_c$（事件增益系数） | 球队实力评级、公司规模、地区禀赋 |
| **阶段状态项** | 随时间变化的“状态/阶段”标记 | $\mathrm{Host}_t$（事件当期）、$\mathrm{Prep}_t$（事件前 $W$ 期） | 政策生效、赛事改制、赛季阶段 |

口诀：**“我过去怎么样（自回归）＋ 我是谁（固有属性）＋ 我现在处于什么阶段（状态）”**。

#### 7.1.2 六条设计准则（按重要性排序）

| # | 准则 | 判定方法与反例 |
|---|---|---|
| 1 | **因果可得性**：$\mathbf{x}_t$ 只能含“站在时刻 $t$ 已公布”的信息 | 逐特征写下“公布时间”。反例（原论文写法）：窗口含 $\mathrm{Gold}_t$ 同时预测 $y_t$ → 同届泄漏，实测 WMAE 由 3.56 虚高到 **0.4–2.7** |
| 2 | **区分“点事件”与“段状态”** | 点事件（发生当期=1）与备战/余波（事件前后若干期=1）要分开，否则丢失“预热—爆发—回落”形态 |
| 3 | **同通道内量纲一致** | 打印每列 min/max/std；0/1 标志位与比值型混放会互相压制。本项目只标准化 $\alpha_c$，`Host/Prep` 保持 0/1 |
| 4 | **按生成机制分通道，不按数据类型** | 成绩序列与事件序列生成过程不同 → 两条 LSTM；混放会让梯度尺度与语义同时打架 |
| 5 | **信息不重复** | 同一信息不要跨通道重复；常量（如 $\alpha_c$）复制到每步时会在大梯度里被累加 $n_{steps}$ 次 |
| 6 | **特征预算** | 经验法则 $n_{feat}\times n_{steps}\lesssim N_{train}/10$；本项目 $5\times3=15\ll114.8$ ✓，超了就降维 |

#### 7.1.3 设计模板（照表填写后即为实现规范）

| 特征名 | 类型 | 时间语义 | $t$ 时刻可得 | 量纲 | 是否标准化 | 进入通道 |
|---|---|---|---|---|---|---|
| $\mathrm{Gold}_t$ | 自回归 | 已发生 | ✅ | 0–83 | ✅ | 目标通道 |
| $\mathrm{Total}_t$ | 自回归 | 已发生 | ✅ | 0–195（重尾） | ✅ | 目标通道 |
| $\mathrm{Host}_t$ | 状态（点） | 当期 | ✅ 提前多年公布 | 0/1 | ❌ 保持原样 | 事件通道 |
| $\mathrm{Prep}_t$ | 状态（段） | 事件前 $W$ 期 | ✅ | 0/1 | ❌ | 事件通道 |
| $\alpha_c$ | 固有属性 | 缓变 | ✅ 只用历史算 | −1–8.39（重尾） | ✅ | 事件通道 |

> 实机输出（`metrics_utils.py --demo` ②）会自动给出“建议标准化 / 保持原样（0/1 标志位）/ 删除（恒定列）”的结论。

#### 7.1.4 三个易错点的判定方法

- **泄漏**：① 把目标期特征置零后性能是否崩塌；② 打乱时间顺序后是否显著变差；③ 给每个特征标注“公布时间”。
- **未来不可知**：预测时点之后才能知道的变量（如某届实际参赛人数）一律剔除。
- **尺度失衡**：审计表 `span` 相差 >10 倍即需标准化；重尾列（span ≫ 中位量级）尤其必须（$\alpha_c$ 最大 8.39）。

### 7.2 损失函数 $\mathcal L$

#### 7.2.1 三层结构（先分层，再选形式）

$$
\mathcal L=\underbrace{\sum_j \alpha_j\,\mathcal L_j^{\text{主任务}}}_{\text{任务类型决定形式}}
+\underbrace{\sum_k \beta_k\,\mathcal L_k^{\text{辅助任务}}}_{\text{表征正则}}
+\underbrace{\mathcal R(\theta)}_{\text{参数正则（dropout / 衰减 / 早停）}}
$$

| 层 | 形式怎么选 | 本项目 |
|---|---|---|
| 主任务 | 回归 → MSE/Huber/分位数；分类 → BCE/CE；排序 → pairwise | 双目标回归 MSE（Gold、Total 求和） |
| 辅助任务 | 选“**标签现成 + 共享表征 + 不泄漏答案**”的第二个任务 | 预测目标期是否主办（BCE） |
| 参数正则 | 优先 dropout/weight\_decay/早停，而不是往损失里加项 | dropout 0.2 + weight\_decay $10^{-5}$ + 早停 |

辅助任务的收益有实测：事件正样本仅 **1.2%**（14/1148），带 BCE 辅助项的版本验证 WMAE **3.562 → 3.396**、事件识别 AUC **0.904 → 0.957**。

#### 7.2.2 设计清单（七问）

1. **主任务输出几个、量纲是否一致？** 一致 → 直接求和；不一致 → 先标准化。
2. **在哪个尺度算损失？** **标准化尺度算损失、原始尺度报指标**（本项目 Total 0–195、Gold 0–83，不标准化必然被大目标主导）。
3. **目标是否重尾/含异常？** 有 → Huber 或分位数损失（本项目含“禁赛记 0”伪影）。
4. **是否需要交付区间？** 需要 → 分位数损失或事后 Bootstrap，**别指望 MSE 给区间**。
5. **有无可用辅助任务？** 三条判定：标签现成、与主任务相关、不泄漏主任务答案。
6. **类别不平衡吗？** → bias 先验初始化（首选）/ `pos_weight` / focal。
7. **$\lambda$ 怎么定？** 见 7.2.3，并报告敏感性。

#### 7.2.3 权重 $\lambda$ 的三种确定方法（按可靠性排序）

| 方法 | 做法 | 适用 |
|---|---|---|
| ① 量级对齐 | 令 $\lambda_i\propto 1/\mathcal L_i^{(0)}$，使各项起点同量级 | **默认首选**，零成本；`recommend_lambdas()` 直接给值 |
| ② 小网格扫描 | 试 $(0.5,0.5),(0.7,0.3),(0.9,0.1)$ 按验证指标选优 | 须报告差异显著性（本项目 15 配置差异全部不显著 → 不要过度调参） |
| ③ 不确定性加权 | $\sum_i\frac{1}{2\sigma_i^2}\mathcal L_i+\log\sigma_i$，$\sigma_i$ 可学习 | 任务多、量纲差异大时 |

#### 7.2.4 四条真实坑（本项目全部踩过）

| # | 坑 | 症状 | 解决 |
|---|---|---|---|
| 1 | **常数写进损失 → 梯度恒为 0** | 原文 $\hat p_i=0.1$ 代入 BCE 得 $\mathcal L_{\text{host}}=2.197\frac HN-\log 0.9$，与参数无关 | 分类头输出 sigmoid 概率；$0.1$ 改用作 bias 先验 $b=\log\frac{p}{1-p}$（实测最优） |
| 2 | **一项淹没另一项** | 未做尺度对齐时 Total 的 MSE 把 Gold 压成噪声 | 目标标准化，或按 7.2.3 ① 对齐 $\lambda$ |
| 3 | **辅助任务泄漏主任务答案** | 如用“明年是否夺牌”当辅助任务 | 辅助标签必须来自独立信息源（赛程/政策公告） |
| 4 | **死项无人察觉** | 总损失正常下降，但某分支毫无贡献 | 逐项记录损失，用 `is_dead_loss()` 检测恒定项 |

### 7.3 WMAE 评价函数

#### 7.3.1 它在评价什么、承担什么角色

WMAE 是**加权 L1**，回答“按业务重要性加权后，平均每单位偏差是多少”，同时承担三个角色：**早停判据、超参选择、交付汇报**。它必须与业务代价一致，否则会挑出“指标好看但业务没用”的模型。

$$
\mathrm{WMAE}=\frac{\sum_c w_c\,|y_c-\hat y_c|}{\sum_c w_c},\qquad
N_{\text{eff}}=\frac{(\sum_c w_c)^2}{\sum_c w_c^2}
$$

#### 7.3.2 权重 $w_c$ 的四种来源（先回答“错谁更疼”）

| 来源 | 定义 | 适用 | 风险 |
|---|---|---|---|
| **规模权重** | $w_c=|y_c|$ | 奖牌榜、营收榜 | 小实体被完全忽略（本项目 28% 样本权重为 0） |
| 重要性权重 | 领域给定 | 政策评估 | 主观，须写明依据 |
| 方差倒数 | $w_c=1/\hat\sigma_c^2$ | 异方差数据 | 需估 $\sigma$，易被异常值主导 |
| 混合 | $w_c=\rho_1|y_c|+\rho_2$ | 兼顾规模与覆盖 | 多一个超参 |

#### 7.3.3 五个必须处理的细节（附本项目实测）

1. **$w=0$ 怎么办**：方案 A 严格排除（报告有效样本量）／方案 B 拉普拉斯平滑 $|y|+1$／方案 C 截断 $\max(|y|,\epsilon)$。
   **实测**：验证集 164 样本中 **46 个（28.0%）权重为 0**；$\mathrm{WMAE}=3.5268$（严格）、$3.1721$（+1）、$1.7553$（无权）。三种口径下**配置排序完全一致** → 结论不依赖该选择。
   ⚠️ 不要用预测值加权（$w_c=|\hat y_c|$），会形成“预测大→权重大”的自激。
2. **有效样本量骤降**：$N_{\text{eff}}=37.8$（严格）/ 52.3（+1）/ 164（无权）——指标实际建立在约 **38 个样本**上，这正是“换种子 WMAE 能差 2–7 枚”的根源。**报告 WMAE 时必须同时报 $N_{\text{eff}}$**。
3. **与 L2 类指标配合看**：本项目验证集 $WMAE=3.53$、$MAE=1.76$、$RMSE=3.38$，差距说明误差在强国身上更厚（重尾）。
4. **禁用 MAPE**：目标含 0 时分母被截断，指标放大到 85%–125%，无解释力；必要时只在“目标 ≥ 阈值”子集上算（本项目金牌 ≥5 子集 MAPE 32.1%）。
5. **不能拿测试集选超参**：作早停判据时验证集必须真正留出（本项目按时间留出 2020/2024）。

#### 7.3.4 可直接复用的实现

```python
def wmae(y_true, y_pred, w):
    s = float(np.sum(w))
    return float(np.sum(w * np.abs(y_true - y_pred)) / s) if s > 0 else float("nan")

def neff(w):                       # 加权有效样本量：指标到底建立在几个样本上
    w = np.asarray(w, float); return float(w.sum() ** 2 / (w ** 2).sum())
```

更多工具见 `代码/metrics_utils.py`：`wmae / wmse / neff / weighted_report / weight_variants / audit_features / recommend_lambdas / event_bias_init / is_dead_loss / check_loss_scale / consistency_checklist`。

#### 7.3.5 设计检查表

- [ ] 权重的业务含义能一句话说清（“谁错更疼”）
- [ ] $w$ 与目标**同口径**（都用当届真实值，或都用历史均值，不混用）
- [ ] 明确 $w=0$ 的处理方式，并报告 $N_{\text{eff}}$ 与零权样本占比
- [ ] 同时报告无权 MAE / RMSE 作为对照
- [ ] 区分“用于模型选择”（早停/调参，用验证集）与“用于最终汇报”（用测试集）
- [ ] 若结论依赖权重口径，必须给出 A/B 两版敏感性结果

### 7.4 三者必须“口径一致”（协同设计流程）

| 典型冲突 | 后果 |
|---|---|
| 输入含泄漏 $\times$ 损失用 MSE $\times$ 指标用 WMAE | 三者同时“变好” → 误以为模型很棒（实测 WMAE 虚高到 0.4–2.7） |
| 损失不标准化 $\times$ 权重按规模 | 大实体主导梯度；WMAE 看似正常，小实体全崩 |
| 辅助项写成常数 $\times$ 只看总损失 | 总损失正常下降，辅助任务其实完全没训练（死项） |
| $w$ 用预测值 $\times$ 用 WMAE 调参 | 指标与模型输出耦合，越调越偏 |

**四步一致性流程**（建议写进每次建模的 checklist）：

```
① 口径一致：输入窗口 / 目标 / 权重 都基于同一时间点可得的信息
② 尺度一致：损失在标准化尺度、指标在原始尺度、权重与目标同尺度
③ 权重一致：w 的来源有业务含义，并明确 w=0 处理与 N_eff
④ 显著性一致：所有“A 比 B 好”的结论都过多种子 + 配对检验
```

`metrics_utils.consistency_checklist()` 可直接打印该检查表并填入本项目取值。
